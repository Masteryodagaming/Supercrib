Investigation (RTDB + code)
--------------------------
Live room TG4DX (Dummy2 vs Dummy, both seats connected) had voice.ready =
[true, false] for minutes — seat 1 never stuck ready=true. UI copy
"Waiting for opponent…" is the bothReady=false branch (not ICE Linking).

Root causes found
-----------------
1) ready=false strand on remount (primary handshake bug)
   start() wrote ready/{seat}=false, then async mic/adopt/announceReady.
   Effect teardown (enabled / bothConnected flicker, Strict-ish remount)
   cancelled before announceReady → RTDB left false while UI still Join/Leave
   + CONNECTING. Peer waits forever. Re-assert only helps if readyAnnounced
   was already true.

2) Dead TURN from prior "fix"
   freeturn.net / freeturn.tel do not resolve in public DNS (ENOTFOUND).
   Prior ICE list was STUN-only in practice for relay NATs. OpenRelay
   openrelayproject/openrelayproject static user/pass is API-gated.

3) Guest answered offers before mic attach → recvonly SDP
   RTDB U2K5B answer had a=recvonly. Guest bindSignaling listened for offers
   during start() before adoptMicStream; host could offer on stale both-ready.
   Guest maybeNegotiate is host-only so late replaceTrack never re-offered.

4) Infinite CONNECTING on ICE fail
   Link watchdog restarted ICE once then stayed on connecting forever — no
   terminal failed state.

Fix
---
1) voicePtt.ts
   - Do NOT write ready/{seat}=false on start(); clear ready only on full
     dispose(stopMic).
   - Ready heartbeat while joined + !live (re-publish true).
   - isSeatVoiceReady() handles RTDB array/map shapes.
   - buildVoiceIceServers(): Open Relay static-auth HMAC TURN
     (staticauth.openrelay.metered.ca + openrelayprojectsecret) + STUN.
   - Queue remote offers until micAttached; flush after adopt/ensureMic.
   - Guest bump voice/renegotiate → host re-offers (late mic / recvonly).
   - needsRenegotiate retried in maybeNegotiate finally (not only on answer).
   - Peer-wait hint (12s) / fail (45s); link-fail (8s after ICE restart) →
     status error with clear copy (not infinite CONNECTING).

2) useSideLiveChat.ts
   - Session effect no longer depends on enabled / bothConnected for PC
     lifecycle (those flickers were cancelling announceReady).
   - Join still requires bothConnected; full teardown only on leave /
     unavailable / no code.

3) SideLiveChatButton.tsx
   - offline/error label → "Failed" (was misleading "Live").
