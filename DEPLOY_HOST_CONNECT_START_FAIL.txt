Ask

Josh (Windows Chrome host): tap Connect voice → brief Failed / "Voice failed to
start" (often no debug line) → UI returns to Connect voice. Phone guest Connect
works. RTDB host ready stays null/false. Preview only. Live untouched.

Root cause
----------
1) onStatus('error'|'denied') dropped joined whenever !debugSnapshot.readyMe.
   readyMe only flipped true from the RTDB onValue listener AFTER announceReady's
   set() resolved — so any concurrent offer/answer/error (common when guest is
   already Connected) saw readyMe=0 and tore down the session before ready stuck.
2) start() early-returned forever on a half-started held session (started=true,
   pc=null) after a throw — Connect retry was a silent no-op.
3) onRemoteOffer with !pc called failClosedDeadSession — raced PC bind when a
   leftover guest offer was already in RTDB.
4) Catch showed a generic "Voice failed to start" with no exception text; debug
   line was gated on joined, so Failed often showed no debug after the drop.

Fix
---
1) Drop joined on session error only when !canPublishReady() (PC/signaling dead),
   not merely !readyMe (RTDB listener lag).
2) announceReady sets localReadyFlag=true optimistically after a successful write.
3) start() recovers partial starts; try/catch clears PC so retry can start again.
   Reused held session with no PC calls start() instead of announceReady-only.
4) onRemoteOffer !pc: stash pending offer + diag, do NOT failClosed.
5) Held zombie recreate helper (started && !canPublishReady).
6) formatVoiceStartFailure surfaces real Error.message; debug stays visible with
   inline error even after joined drops (lobby button + OnlineLobby).
