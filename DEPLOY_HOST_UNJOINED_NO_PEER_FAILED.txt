Root cause
----------
1) OnlineLobby blamed peer whenever joined && !live — no readyMe/peerReady gate.
   So any Failed/offline (peer-wait 15s, remount fail-closed, dead session) showed
   “{peer} needs Connect” even when self never published ready (readyMe=0).
2) Peer-wait timers started at session start() and Failed on !bothReady after 15s
   without requiring localReady — so readyMe=0 could still surface Failed.
3) Fail-closed / mic-fail left joined=true → Failed badge stuck; Connect re-tap
   was a no-op while joinedRef stayed true.

Fix
---
1) UX helpers (useSideLiveChat): shouldShowPeerNeedsConnect / shouldPulseConnectVoice /
   effectiveLobbyVoiceJoined / shouldPeerWaitFail / deriveLobbyVoiceHint.
   - !joined or (offline && !localReady) → pulse Connect; NEVER peer-blame Failed.
   - Peer “{name} needs Connect” ONLY when joined && localReady && !peerReady.
2) voicePtt: schedulePeerWaitTimers only after localReady sticks; Failed gated by
   shouldPeerWaitFailClosed(localReady). Seat-aware wait copy.
3) Mic denied → “Allow microphone, then tap Connect voice”.
4) Fail-closed / mic-fail / start-fail / onStatus error with !readyMe → drop joined
   so Connect pulses and re-tap works.
5) OnlineLobby + App pass localReady/peerReady into lobby voice UI.
