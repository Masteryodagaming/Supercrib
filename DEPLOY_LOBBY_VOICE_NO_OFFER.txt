Root cause
----------
1) shouldOfferOnceWhenBothLobbyReady lived only in unit tests — production
   Connect path relied solely on VoicePttSession.kickNegotiate/maybeNegotiate.
2) maybeNegotiate hard-gated on micAttached. Host ready=true with mic never
   attached (reuse-session early-return skipped pending-mic adopt after
   Table/StrictMode remount) → offer never written; guest Linking forever.
3) Guest wait message was soft / 10s; host had no "offer never published" fail.

Hard fix
--------
1) voicePtt.ts
   - OFFER_RETRY_MS 2s → 1s; GUEST_OFFER_WAIT_MS 10s → 5s
   - GUEST_NO_HOST_OFFER_MSG = "Host didn't send offer — reconnect"
   - After both-ready: always startOfferRetryLoop; after 1s without mic,
     allowOfferWithoutMic + force createOffer (transceiver already sendrecv)
   - scheduleHostOfferPublishFail if offer SDP never lands in RTDB
   - ensureLobbyHostOffer() / hasPublishedOffer() / isBothReady() public API
2) lobbyVoice.ts
   - Wire shouldOfferOnceWhenBothLobbyReady into kickLobbyHostOfferIfNeeded
     (production Connect calls this — no longer tests-only)
3) useSideLiveChat.ts
   - Reused session no longer early-returns before pending-mic adopt
   - Always kickLobbyHostOfferIfNeeded after announceReady
4) Tests: both-ready → host must offer; guest fail copy
