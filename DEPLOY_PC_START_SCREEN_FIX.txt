What caused the tile
--------------------
Splash renders inside `.app`. Felt menu-lock (all image felts × menus) had:

  .app[class*="felt-"]:not(.app-playing) > * { position: relative; z-index: 1; }

Higher specificity than `.splash-screen { position: fixed }`, so when ZF
(or Dumpster) felt was equipped at boot, Splash lost viewport-fixed and was
trapped in the desktop phone shell (max-width ~680/780). The portrait
lockup `contain`-fitted that narrow column (dark-green block); outside it,
the fixed felt `::before` / html letterbox showed ZF ZERO|FORGE side rails —
looked like tiled/cropped side fragments. Classic green (no felt-* class)
never hit the rule, so phone / non-ZF looked fine.

CSS fix (src/ui/styles.css only — no board clamps / in-match)
-------------------------------------------------------------
1) Menu-lock child stacking excludes splash:
     .app[class*="felt-"]:not(.app-playing) > *:not(.splash-screen)
2) Explicit restore viewport-fixed for splash under .app / felt-*:
     .app[class*="felt-"]:not(.app-playing) > .splash-screen,
     .app > .splash-screen
   → position:fixed; inset:0; 100dvw×100dvh; z-index:200; no shell
     max-width / radius / shadow
3) .splash-stage: keep background-size:contain + no-repeat + solid
   #020d07 letterbox; wide PC media reinforces contain/no-repeat
   (never 100% 100% stretch, never repeat)
