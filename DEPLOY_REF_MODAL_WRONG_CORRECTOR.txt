Josh’s Competitive flow (desktop-preview only; do NOT promote live; no voice/chat):
1. Claimant announces hand → opponent Approve or Adjust.
2. On Adjust → clear Ref modal (not a one-line toast) before continuing.
3. If adjuster (corrector) is wrong → penalize adjuster (peg).
4. Then existing Muggins step if underclaim, showing points available.
5. Modal shows Original hand, Opponent adjusted to (or Approve path skips),
   True, Verdict. Keep blank Adjust keypad, original hand in HandBlock,
   sticky Approve/Adjust, hand wording. Online + AI Dummy2.

Penalty rule (exact)
--------------------
Wrong-corrector peg when Adjust ≠ true raw:
  penalty = |adjusted − trueRaw| × showMultiplier
  (×2 non-spade starter, ×1 spade — same shape as overclaim steal).
Applied to the **adjuster** (review respondent), not the claimant.
- Adjuster exact (adj === true) → 0 (no wrong-corrector).
- Claimant already exact + wrong Adjust → keep claimant; still penalize adjuster.
- Neither exact → keep closer (claimant on tie); if adjuster still ≠ true,
  still penalize adjuster by the rule above.
Approve path: no Ref modal, no wrong-corrector penalty.

Ref modal (blocking pendingRef)
-------------------------------
After Adjust resolves vs true raw (kept number + any overclaim/underclaim peg):
  Original hand: N
  Opponent adjusted to: M
  True: T
  Kept: K
  Verdict: e.g. “Adjuster right”, “Claimant was already exact — adjuster wrong,
    penalized −P”, “Neither exact — kept claimant/adjuster (closer); …”
  Wrong-corrector penalty line when P > 0.
Continue dismisses pendingRef → then Muggins Accept / Muggins +missed (if any),
or next claim. AI does not auto-advance past pendingRef.
