Root cause
----------
One-way fix set shouldAnswerOfferWithoutMic() → false (correct: wait for
sendrecv mic before createAnswer) BUT start() still always wrote
ready/{seat}=true before adoptMicStream (void shouldAnnounce — "always
announce now").

Race:
1) start() → ready=true (no mic yet)
2) peer also ready → bothReady
3) guest offer arrives; answer deferred (answer-wait-mic)
4) host link watchdog @ 3.5s ICE-restarts / clears answer
5) blind renegotiate bumps after late mic / Live (ensureOutboundAudio +
   bumpRenegotiateAfterMicIfNeeded) thrashed Safari SDP further
6) Result: Failed / no Live UI, no remote audio; game SFX often silent
   after failed voice audio-session churn on iOS

Also: remote ontrack accumulated tracks without dropping superseded audio
→ Safari could stick on an ended silent track after renegotiate.

Fix (targeted; keep sendrecv)
-----------------------------
- Honor start({ announceReady: false }); stayReady still set at PC bind.
- useSideLiveChat: start({ announceReady: false }) → adopt/ensure mic →
  announceReady() (ready only after mic on sender).
- Ready heartbeat interval only publishes when isMicAttached().
- shouldBumpRenegotiateAfterMicAttach → false while wait-for-mic answers
  (no recvonly-first residue to upgrade); stop blind Live bumps.
- shouldBumpOutboundUpgradeOnLive: only if currentDirection is
  recvonly/inactive (belt-and-suspenders).
- accumulateRemoteAudioTrack: replace prior audio tracks on renegotiate.
- Kept: wait-for-mic answers, force sendrecv, SDP enable/restore, VAD
  clone on ensureMic, unmute→play retry.
