Root cause
----------
Only construction site was voicePtt VoicePttSession.start():
  const pc = new RTCPeerConnection({ iceServers: [...VOICE_STUN_SERVERS] });
Free global — no shadowed local, no wrong import, no vitest mock in the app
bundle (dist had a single bare `new RTCPeerConnection`). Chrome reports
"RTCPeerConnection is not a constructor" when that binding resolves to a
non-function (typically undefined): WebRTC disabled / enterprise policy /
flags / extension overwrite on the PC browser. Phone still exposes a working
ctor, so the same preview JS succeeds there. Bare `new` gives a cryptic TypeError
instead of a clear "WebRTC missing" message.

Fix
---
1) resolveRTCPeerConnectionCtor() — read
   globalThis.RTCPeerConnection ?? window.RTCPeerConnection ?? webkit…
   and require typeof === 'function'; throw RTCPEERCONNECTION_MISSING_MSG if not.
2) start() uses `const PeerConnection = resolveRTCPeerConnectionCtor();
   const pc = new PeerConnection(...)` — never shadow the global with a
   same-named non-ctor value.
3) Unit tests: happy path, window fallback, missing → clear error, object
   shadow rejected.
4) VAD / lobby hold / prior race fixes untouched.
