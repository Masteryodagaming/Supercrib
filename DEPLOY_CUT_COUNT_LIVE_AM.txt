Root cause
----------
Side-chat hit-target pass (Join moved into .meta-leading) regressed table
stacking / clip:

1) `.meta { z-index: 32 }` created a high stacking context over mid-zone
   (z 8–10). CutFan + COUNT lived inside mid-zone and lost to hand (z 14)
   and header chrome when space tightened.
2) Mid-zone used `overflow-x: hidden` + `overflow-y: visible`, which CSS
   computes to overflow-y: auto — clipping CutFan / COUNT when the taller
   header (44px Join) squeezed mid-zone under `.table { overflow: hidden }`.
3) Waiting / watch cut fans used `:disabled { opacity: 0.55 }`, so the
   non-cutter fan looked washed out / “gone” on phone.

Fix
---
1) `.meta` z-index 32 → 12. Join control keeps z-index 32 on
   `.meta-leading` / `.table-side-live-chat` only.
2) Cut + pegging (and discard/show) mid-zone z-index → 18 (above hand 14);
   `overflow: visible` both axes so COUNT / CutFan are not clipped.
3) `.cut-panel { flex-shrink: 0 }`; pegging mid-play-row overflow visible.
4) `.cut-for-deal-meta { z-index: 1 }` so deal-cut header never paints over
   the fan body.
5) Full opacity for `.cut-watching` disabled cards (starter CutFan +
   DealCutFan watchMode).
6) Compact Join button min-height 44→36 (desktop 40) so header steals less
   mid-zone height. Chat still preview-hostname gated.
